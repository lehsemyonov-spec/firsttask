# Шаг 6. План проверки и итог

**Цель:** договориться, как поймём, что стратегия работает, и зафиксировать решение.

**Вход:** утверждённые стратегии, `unknowns.md`.
**Выход:** `validation-plan.md`, `decisions.md`, `summary.md`, `deliverable.md` (если заказчик задал формат), `report.md`.
**Методички:** `knowledge/validation.md`.

## Действия

1. В `validation-plan.md`: ожидаемое изменение (метрика, на сколько, к какому сроку), с чем сравниваем (контроль, прошлый период, сегмент), срок наблюдения, нежелательные последствия и как за ними следить, критерий решения (продолжаем / меняем / останавливаем).
2. Свяжи план с пробелами: каждый критичный пункт `unknowns.md` либо закрывается проверкой, либо явно остаётся риском.
3. В `decisions.md` запиши принятое решение: что решили, на каких фактах/гипотезах `[F…]` оно держится, кто ответственный (роль, не ФИО), когда и при каком условии пересматриваем.
4. Заполни `summary.md` — первую страницу отчёта: рекомендация (с выбранным вариантом `O…`), три основания со ссылками `[F…]` (не синтетика), три риска, что решить сейчас (со сроком).
4а. **Документ по структуре заказчика.** Если в `brief.md › Формат результата` есть список частей — собери `deliverable.md`: один раздел `## …` на каждую часть, теми же названиями и в том же порядке. В каждой части — то, что заказчик в ней просил, со ссылками `[F…]`; расчёты — рядом с решением, которое они обосновывают (итог и ссылка на скрипт в `analysis/`). Новых сведений не добавляй — всё берётся из рабочих файлов. Требования заказчика, которых нет в шаблонах (например, план по кварталам, ресурсы, риски), сначала допиши в рабочие файлы (`validation-plan.md` › необязательные разделы), потом перенеси в документ.
5. Собери итоговый документ: `python tools/strategist.py report <slug>` → `report.md`, резюме в нём идёт первым, за ним — документ по структуре заказчика (если есть), рабочие файлы — приложениями. Проверь, что он читается без остальных файлов.
6. Итоговая сводка человеку: содержание `summary.md` и стоимость проекта (`cost summary`).

## Критерии готовности

- Все разделы плана проверки заполнены.
- В `decisions.md` есть запись с основаниями и условием пересмотра.
- `summary.md` заполнен: у каждого основания есть ссылка на факт, выбранный вариант назван.
- Если формат задан — в `deliverable.md` есть раздел на каждую часть из «Формата результата».
- `check --step 6` проходит без ошибок; `report.md` собран.
