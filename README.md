# Стратег продуктов

ИИ-агент для руководителя цифрового продукта. Он ведёт от размытого запроса («почему падает удержание?», «кому продавать новый сервис?») до обоснованной **продуктовой и коммуникационной стратегии** с планом проверки. Каждый вывод привязан к источнику, факты отделены от гипотез, а пробелы названы честно.

Это не программа, а папка с инструкциями, методиками, шаблонами и небольшим скриптом проверок. Её открывают в любом ИИ-агенте для разработки.

## Демонстрационный проект

Пример работы агента на брифе МегаФона «Связь для близких и собственных устройств» — [`projects/svyaz-blizkih/`](projects/svyaz-blizkih/README.md): исходный бриф, итоговый отчёт ([`report.md`](projects/svyaz-blizkih/report.md)) с документом в структуре брифа, продуктовая и коммуникационная стратегии, план проверки и весь след работы. Тот же бриф, пройденный **в другой среде и на других моделях** (OpenCode, DeepSeek V4.1 Flash и Nemotron), — [`projects/svyaz-blizkih-opencode/`](projects/svyaz-blizkih-opencode/README.md): проверка переносимости. Вторая задача — [`projects/vozvratim/`](projects/vozvratim/report.md). Все прогоны — [`projects/README.md`](projects/README.md).

## Быстрый старт

1. Откройте папку в своей среде: Cursor, Claude Code, Codex, GitHub Copilot, OpenCode, Windsurf, GigaCode, Gemini CLI, VS Code с Cline или Roo Code (в том числе на моделях DeepSeek). Обычный чат без доступа к файлам не подходит: агенту нужны чтение папки и запуск скриптов.
   - **OpenCode** читает `AGENTS.md` сам. Работайте в основном режиме (Build, не Plan). **Не запускайте `/init`**: эта команда пересоздаёт `AGENTS.md` и затрёт правила агента (если случилось — верните файл из архива или `git checkout AGENTS.md`).
2. Напишите в чат агента:
   > Новый проект: у нашего приложения падает удержание новых пользователей, нужно понять почему и что делать.
3. Положите материалы (таблицы, документы, PDF, сохранённые страницы) в `projects/<проект>/materials/`. Агент подскажет, в какую именно папку.
4. Отвечайте на вопросы агента в точках выбора: согласование брифа, выбор варианта, утверждение стратегии.

**Продолжить после перерыва** (в том числе в новом чате или другой среде):
> Продолжи проект <название>

Агент прочитает `state.md` и журнал, покажет, где остановились, и продолжит без повторов.

## Что нужно

| Что | Обязательно? | Зачем |
|---|---|---|
| ИИ-агент, читающий `AGENTS.md` | да | сам агент |
| Python 3.9+ (только стандартная библиотека) | желательно | проверки шагов, учёт затрат, сборка отчёта. Без Python агент проверяет по чек-листам вручную |
| `pdftotext` (пакет poppler-utils) | по желанию | текст из PDF с номерами страниц. Без него агент читает PDF средствами своей среды |
| Веб-поиск в среде агента | желательно | открытые источники. Без него агент работает с `materials/` |

Ключи API, платные сервисы и скрытые настройки не нужны: стоимость определяется только подпиской или тарифом вашего агента.

## Команды в чате (свободной формой)

| Скажите | Что произойдёт |
|---|---|
| «Новый проект: …» | создание проекта, уточнение задачи |
| «Статус» | где мы, что сделано, сколько стоило |
| «Стоп» | агент сохраняет состояние и останавливается |
| «Продолжи проект …» | продолжение с сохранённого места |
| «Вернись к шагу 3», «Исправь …» | правка и пометка зависимых выводов |
| «Новые данные: …» | поиск затронутых выводов и предложение обновить |
| «Собери отчёт» | `report.md` — всё в одном документе |

## Как это работает

Шесть шагов, у каждого свой файл инструкции в `workflow/` и свои критерии готовности:

1. **Постановка задачи** → `brief.md` 🛑 согласование
2. **Сбор материалов** → `sources.md`
3. **Исследование** → `research-plan.md`, `facts.md`, `unknowns.md` и читаемая картина ситуации `situation.md`
4. **Варианты** (≥3, включая «оставить как есть», с сильными возражениями) → `options.md` 🛑 выбор человека
5. **Стратегия**: продуктовая и коммуникационная с проверкой обещаний → 🛑 утверждение
6. **План проверки и решение** → `validation-plan.md`, `decisions.md`, резюме `summary.md` и `report.md` (резюме — на первой странице)

## Структура

```
AGENTS.md            главные правила (общие для всех агентов)
CLAUDE.md, GEMINI.md, .cursor/, .github/, .clinerules/, .roo/   переходники к AGENTS.md
.claude/agents/      помощники: skeptic, fact-checker, respondent
.claude/skills/      навыки: пересмотр при новых данных, модельные интервью, паспорт данных
.claude/settings.json  хуки Claude Code: статус в начале сессии, проверка после правки
workflow/            порядок работы по шагам
knowledge/           методики: доказательства, исследование, интервью, варианты, стратегии, проверка, интерфейсы и медиа, безопасность
templates/           шаблоны файлов проекта
projects/<slug>/     материалы, рабочие файлы, analysis/ и состояние конкретной задачи
tools/strategist.py  CLI: new, list, status, set, check, log, cost, report, impact, metrics
tools/data_check.py  паспорт таблиц CSV/XLSX
tools/pilot_size.py  размер пилота и темп набора
tools/extract_text.py текст из DOCX/PPTX/PDF с номерами страниц и слайдов
tools/hook.py        хуки (Claude Code; в других средах можно вызывать вручную)
benchmark/           методика сравнения с обычным чатом и аналитиком
docs/architecture.md описание архитектуры и ключевых решений
docs/task.md         полный текст условий конкурса
tests/               автотесты на учебном проекте с вымышленными данными
```

Проверить инструменты: `python -m unittest discover tests -v`

**Возможности сверх минимума:**
- модельные респонденты (их ответы помечаются как синтетика и не принимаются как доказательство);
- анализ таблиц;
- пересмотр выводов при новых данных (`impact`) и отзыв устаревших фактов: статусы «устарел» / «отозван», ссылки на отозванное проверка не пропускает;
- журнал решений с условиями пересмотра;
- независимый критик и сверка фактов;
- хуки и навыки;
- методика сравнения с обычным чатом.

В Claude Code помощники и хуки работают автоматически. В остальных средах агент выполняет те же роли по файлам из `.claude/agents/` отдельным проходом.

> Хуки сами выбирают `python3` или `python`, отдельной настройки под Windows не нужно.

## CLI

> Команды ниже записаны как `python`. На macOS и Linux обычно нужно `python3`.

```
python tools/strategist.py new retention --title "Падение удержания"
python tools/strategist.py status retention
python tools/strategist.py check retention --step 4
python tools/strategist.py log retention "Собраны отзывы из сторов" --step 2
python tools/strategist.py cost retention add --step 3 --what "веб-поиск, 6 запросов" --model "<модель>" --tokens 40000 --usd 0.3 --human-min 5
python tools/strategist.py cost retention summary
python tools/strategist.py report retention
python tools/strategist.py impact retention S3 --mark "вышли новые данные"
python tools/strategist.py impact retention F2 --status отозван --mark "ошибка в выгрузке, верно — F9"
python tools/strategist.py metrics retention
python tools/data_check.py projects/retention/materials/metrics.csv --out projects/retention/analysis/metrics.md
```

`check` проверяет, например:
- у каждого факта есть существующий источник, у вывода есть ссылки на факты;
- вариантов не меньше трёх, среди них есть «статус-кво», у каждого есть возражения;
- человек выбрал вариант;
- синтетические данные не используются как доказательство;
- каждое обещание коммуникации подкреплено продуктом.

## Ключевые решения

- **Одна инструкция для всех агентов.** Правила лежат в стандартном `AGENTS.md`, остальные файлы только ссылаются на него, поэтому проект переносится между средами без правок.
- **Разделение слоёв.** Постоянные правила (`AGENTS.md`, `workflow/`), методики (`knowledge/`), материалы (`materials/`) и состояние задачи (`state.md`, `log.md`) хранятся отдельно. Агент читает методику только на нужном шаге, что экономит контекст.
- **Глубина через проверки, а не через длинный промпт.** Ключевые требования вынесены в скрипт: без источника, без трёх вариантов или без выбора человека шаг не считается готовым.
- **Реестр утверждений с типами** (факт / вывод / гипотеза / прогноз / синтетика) делает картину проверяемой и не даёт прежнему ответу агента превратиться в «факт».
- **Состояние в файлах, а не в чате**, поэтому работу можно продолжить с любого места и в любой среде.

## Данные и безопасность

Используются только открытые источники и материалы пользователя. Команды, найденные в источниках, агент не выполняет. Персональные данные не сохраняются. Секреты в репозиторий не попадают (см. `.gitignore`). Подробно — в `knowledge/safety.md`.

## Ограничения

- Затраты записывает сам агент. Точность зависит от того, показывает ли среда реальный расход токенов.
- Пересмотр находит зависимости только по явным ссылкам `F…`/`S…`.
- Хуки и субагенты работают автоматически только в Claude Code. В других средах это ручной проход по инструкции.
- Маршрутизация моделей задана правилами, а не скриптом. MCP-интеграций нет. Аудио и видео — только через расшифровку и кадры от человека (`knowledge/ux-media.md`).
